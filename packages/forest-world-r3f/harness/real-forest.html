Storytree's real forest, through the 3D renderer

Nobody had seen it. Every forest picture the land work has produced was either a synthetic crowd — copies of one fixture island on a scatter grid calibrated to a land share read off a PNG, which models density and knows nothing of the map's topology — or a ladder arm, the real layout drawn with a candidate spacing or tile the map does not ship. This page renders exactly one thing: the layout the studio built for the live corpus, asked for nothing, pushed through the shipped 3D pipeline (worldTo3D, dressMapWithCover, shippedGroundBuild, buildGroundMaterial) and photographed.

It decides nothing and changes no shipped surface. It is a picture and four numbers. It is not a precondition for mounting the land (ADR-0546 D3): the owner accepted the forest's shape after the un-projection sight-unseen, as an offered option he was shown and declined. If the picture reads badly, that is a finding and a fresh question about the forest's spacing — never a licence to re-squash it here.

The two surfaces do not share a projection, so “the same framing” is defined rather than assumed. The studio's SVG map draws a world already projected at 20°; this canvas stands the same world on true ground and looks at it from 50°, so depth delivers 2.24× more screen height here than there. Neither projection touches x. So fit fits the whole forest into the buffer at each renderer's own scale (comparable as pictures), and matched renders at the 2D map's own delivered pixels-per-world-x-unit (comparable as a measurement).
